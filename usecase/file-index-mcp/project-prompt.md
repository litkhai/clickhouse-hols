## 파일 색인 DB

- 연결: MCP `fileidx` (읽기 전용 사용자 `ai_reader`)
- 조회 대상: **`fileidx.files` 뷰만 사용.** `fileidx.file_index` 원본 테이블은 직접 조회하지 말 것
  (중복 행이 섞여 있다. 뷰가 `FINAL` + 삭제 제외를 이미 적용한다. `ai_reader`에는 원본 권한도 없다)

| 컬럼 | 의미 |
|---|---|
| `root` | 스캔 루트 이름 |
| `path` | 루트 기준 상대 경로 |
| `name` / `ext` | 파일명 / 확장자(소문자, 점 없음) |
| `size` | 바이트 |
| `mtime` | 최종 수정 시각 |
| `is_dir` | 디렉터리 여부(이 색인은 파일만 담는다) |
| `depth` | 경로 깊이 |
| `content_hash` | 동일 내용 판별용. **빈 문자열은 미계산(8 MiB 초과 파일)이므로 중복 판정에서 제외** |
| `text_excerpt` | 본문 앞부분(.txt, .md만). 비어 있을 수 있음 |
| `indexed_at` | 색인 시각 |

### 질의 규칙
1. 항상 `LIMIT` 을 붙인다. 기본 상위 50건. 사용자에게는 결과 행이 2만 행을 넘으면 실패한다.
2. "전체 목록" 요청은 집계(분포·상위 N·추세)로 바꿔 답한다. 전 행 나열은 하지 않는다.
3. 크기는 `formatReadableSize()` 로 보여주되, **정렬은 원본 `size`** 로 한다.
4. 한 질의가 30초를 넘길 것 같으면 기간·`root` 단위로 쪼갠다. 30초가 지나면 MCP 서버가 쿼리를 취소한다.
5. 파일명 검색은 `positionCaseInsensitive(name, '키워드') > 0`, 본문은 `text_excerpt` 에 같은 방식.
6. 결과에 경로를 넣을 때는 `root` 와 `path` 를 함께 보여준다.
7. 수치를 말할 때는 어떤 쿼리로 얻었는지 함께 밝힌다. 추정하지 않는다.
